# Exercise Patterns

Choose one exercise that tests one learning objective. Keep it disposable.

## Explain and transform

Use when introducing a concept.

1. Explain the concept in plain language.
2. Identify it in a familiar game or everyday system.
3. Show a counterexample.
4. Ask Robert to transform the concept into a different theme or context.
5. Ask what player experience the transformation might change.

## Three mechanic alternatives

Use when an intended experience is clear but the mechanism is not.

Generate three alternatives that differ structurally, not cosmetically. For
each, state the player action, information, constraint, trade-off, predicted
experience, and primary risk. Preserve Robert's option to combine or reject all
three.

## One-rule prototype

Use when a mechanic is still abstract.

Create the smallest rules sketch that lets someone make the target decision.
Omit story, progression, polish, and content unless one is necessary to answer
the question.

## Decision table

Use when choices or consequences are difficult to compare. Map player state,
available information, alternatives, immediate consequence, delayed
consequence, and likely strategy. Look for dominated choices and missing
feedback.

## Paper loop

Use cards, tokens, dice, a map, or written state to represent the core loop.
Run several turns manually. Record where decisions become obvious, confusing,
or irrelevant.

## Causal system sketch

Use when two or more mechanics interact over persistent state.

1. Name one intended player experience and one bounded system question.
2. Identify actors, state, resources, information, rules, and time horizon.
3. Draw signed causal links and mark delayed effects.
4. During a player-facing manual run, record what the player knows, their
   materially different alternatives, the selected action, and why no
   alternative universally dominates.
5. Run three to five manual turns or scenarios.
6. Identify one reinforcing loop, one balancing force, one failure risk, and
   one unknown.
7. Finish through the exercise closeout. Treat any lesson as a candidate and
   retain nothing automatically.

## Rule subtraction

Use when a concept is becoming overbuilt. Remove one rule, resource, phase, or
exception. Predict what experience disappears and what becomes clearer. Keep
the removal only if evidence supports it.

## Opposite design

Use when the current framing feels inevitable. Design a credible version that
optimizes the opposite experience: cooperation instead of competition,
expression instead of mastery, uncertainty instead of control, or brevity
instead of accumulation. The point is to reveal assumptions, not force the
opposite direction.

## Observation-first playtest

Use after a playable form exists. Give the player the minimum necessary
instruction, observe what they attempt, and avoid teaching the intended
strategy during the test. Debrief afterward. Obtain consent before retaining
feedback, recordings, identifiers, or telemetry.

## Exercise closeout

End every exercise with:

- concept practiced;
- Robert's current explanation;
- decision made;
- prediction;
- observation or `not yet tested`;
- one revision;
- candidate human lesson;
- candidate agent lesson;
- next smallest question.
